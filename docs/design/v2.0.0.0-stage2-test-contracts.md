## 5. 每个 Stage 3 task 的 RED/GREEN/refactor/regression/impact/acceptance 合同

### 5.0 通用约定（所有任务共用）

- **RED 判定标准**：命令 exit code 非 0 或断言失败匹配 `预期失败`；**禁止**「测试文件不存在」作为 RED；**禁止** mutation-as-RED（项目 authority 覆盖 skill 示例，§1.1）；RED 只来自未修改 live HEAD 的真实行为缺陷，且只存在于 G1-G11 实现任务。
- **已实现义务**：只给 existing GREEN/regression evidence 命令（断言既有行为、预期通过、保存 receipt），不创建实现任务。
- **receipt**：`docs/design/receipts/<TASK_ID>/red-<n>.txt` / `green-<n>.txt`；含完整命令、exit code、关键输出行、utc 时间戳；RED receipt 附 `git rev-parse HEAD` 证明未改源码。
- **focused**：`npm test -- <文件>`；**affected**：同 seam 既有测试；**architecture**：`npm run validate:architecture`；**broad**：`npm run validate`。
- **GitNexus impact**：修改 symbol 前 `node .gitnexus/run.cjs impact "<symbol>" --repo paseo-agy-acp`；HIGH/CRITICAL → 报告 Controller + 扩大回归到 `tests/acp-server.test.ts`/`tests/acp-runtime-wiring.test.ts`/`tests/queue-steer.test.ts`/`tests/cli.test.ts` 全链。
- **detect_changes**：commit 前 `node .gitnexus/run.cjs detect-changes --repo paseo-agy-acp`，选择性暂存本任务文件。
- **诊断循环（diagnosing-bugs）**：RED 意外变绿 / regression 意外变红 → `观察→假设(≥3)→实验(单变量)` 循环，禁止先改实现；确认真实行为后决定升级 blocker。

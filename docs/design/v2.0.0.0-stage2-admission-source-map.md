### 3.2 Ownership seam

Admission Controller owns only account-scoped queue, seat, start gate, lease/heartbeat observation, cooldown, payload and recovery evidence. ACP Connector owns ACP protocol, session/conversation state, Antigravity process, StreamPoller, Translator, permission, cancellation and client notification. The only intended composition is the request-scoped AgyAdmissionDispatchBoundary at ACP Connector/agy/cli.ts:285 and the coordinator call from ACP Connector/acp/session/prompt.ts:393. The admission fence SHALL bracket only the first irreversible BUSINESS PROMPT write; permission-key PTY writes remain in the existing ACP permission chain and are not business-prompt dispatch.

The source currently has a real seam for a synchronous boundary. Production `runPromptCommand` executes `prepare -> beforePromptWrite -> one stdin write -> afterPromptWrite` at `ACP Connector/agy/cli.ts:1132-1142`, but it does not consume the accepted/ambiguous three-state result from the prompt-free process primitive at `ACP Connector/agy/prompt-free-process.ts:77`. This is a source-level integration gap, not proof that the existing hooks or primitive are absent.

## 5. v1/v2 API、data、event、permission 与 process contract

### 5.1 Admission state machine

当前 RequestState 在 Admission Controller/controller.ts:43 声明为：

queued -> admitted -> starting -> dispatch_intent -> active -> provider_terminal -> completed/failed/cancelled

并行的安全终态或不确定路径为：

1. queued -> queue_timeout；
2. queued -> `cancelled(reason=queued_owner_dead)`，仅在 durable owner binding 与完整进程证据证明 owner exit、request 从未获取 lease/dispatch 时；同事务删 payload/移除队列占位，零 replay，恰好一个 cancel terminal；
3. admitted/starting/dispatch_intent -> failed 或 cancelled，仅在 abandonBeforePrompt 的 no-write proof 下；
4. starting/dispatch_intent/dispatch_ambiguous/active -> recovery_required；
5. recovery_required 或其他 unresolved local execution -> local lease release，同时 request 保持 recovery_required；
6. dispatch_intent -> dispatch_ambiguous，不得自动继续写或 replay。

SanitizedEventKind 的 allowlist 位于 Admission Controller/controller.ts:1492。events 表与 journalTransition 只保存状态转换、时间和 correlation HMAC；它不是 outbox、delivery claim 或 client replay ledger。

**Stage 3 单一 terminal contract**：Admission 只负责产生/持久化 `cancelled|queue_timeout|provider_failure|recovery_required` 分类与 seat-release 状态，唯一 prompt-turn terminal emitter/owner 是 `ACP Connector/acp/session/prompt.ts`。verified queued-owner exit 是 cancellation：类型为 `cancelled`，typed reason 为 `queued_owner_dead`，不得归为 `recovery_required`。v2 每 turn 恰好发一个 `state_update{state:"idle",stopReason:<code>}`；`stopReason` 为开放字符串，本轮输出集为 `end_turn|cancelled|queue_timeout|provider_failure|recovery_required`。v1 每 turn 恰好返回一个 `PromptResponse`：成功=`end_turn`；取消（包含 queued-owner death）=`cancelled` 且 `_meta["agy-acp/turnTerminal"]={version:1,code:"cancelled"}`；queue timeout/provider failure/recovery_required=`refusal` 且同一 typed meta 的 code 为对应分类。已知 Scheme 失败不得 raw RPC throw、不得 `end_turn`。`ACP Connector/acp/terminal/index.ts` 只负责 execute-tool terminal display；`ACP Connector/acp/session/update-wire.ts` 只转换 streamed `session/update` payload；两者都不取得 prompt-turn terminal ownership。

### 5.3 Permission 与 auth

Scheme §4.2、§4.7 要求启用和关闭两条路径都保留现有 permission chain。legacy path 的 AgyCliSession.prompt 通过 ACP v1/v2 adapter 的现有 permission callback（ACP Connector/acp/session/prompt.ts:450-453、:524-545）继续转发 permission；permission-key PTY writes 是该 chain 的控制输入，ACP Connector/agy/cli.ts:515-519 明确它们不是 adapter business prompt。Admission 的 fence 只能包住第一次不可逆 BUSINESS PROMPT write（ACP Connector/agy/cli.ts:1132-1139），不能把 permission-key writes 当作 business prompt dispatch。

当前 enabled path 没有满足该 preservation duty：ACP Connector/acp/session/setup.ts:44-49 在 admissionEnabled 时强制 dangerously-skip-permissions 并关闭 promptInArgv；ACP Connector/acp/agent.ts:480-488 在 turnAdmission 存在时拒绝其他 mode；ACP Connector/agy/cli.ts:535-541 在有 admissionBoundary 时拒绝 interactive permission。于是当前 coupling 是 ADM-P01 的 Scheme deviation，归 Stage 3 修复；现有 mode/callback 测试只能证明 legacy path 或 bypass path，不能证明 enabled path 保留 permission chain。

但 ACP Connector/acp/agent.ts:278 authenticate、:282 loginAuth、:286 logout、:291 logoutAuth 没有在 Admission enabled 时 fail closed。confirmed Scheme 的 online login/logout gate 因而是独立 Stage 3 repair；不得用现有 auth tests 的 green source 当作 Admission contract 已完成。

### 5.4 Prompt/process contract

当前 prompt-free process 是 stdin-only：ACP Connector/agy/prompt-free-process.ts:10-15 定义 accepted/ambiguous，:110-126 保证一次 write、EOF 后只返回 accepted 或 ambiguous，:128-134 发送 SIGINT。dispatch-boundary.ts:166-173 保证 durable commit 后同一 synchronous stack 调用一次 write。

Admission 的 controller boundary 则在 ACP Connector/admission/turn-coordinator.ts:331-363 采集 child process identity、记录 process identity/dispatch intent、检查状态并 markActive。成功后 Admission Controller/controller.ts:601-609 删除 payload。该 contract 在 fake process tests 中成立。

生产 integration 仍在 `ACP Connector/agy/cli.ts:1132-1142`：`prepare/beforePromptWrite` 与 `afterPromptWrite` hooks 已存在，单次 stdin 写位于两者之间；缺口是没有调用 `AgyPromptFreeProcess.writeBusinessPrompt`，也没有将其 accepted/ambiguous 三态结果映射到 `markActive`/`dispatch_ambiguous`。此处是唯一允许的 Stage 3 integration seam；不能新增第二套 output/delivery authority。

## 7. Transaction、locking、concurrency 与 fault contract

### 7.1 Durable transaction contract

1. AdmissionController constructor 在 Admission Controller/controller.ts:385-390 开启 foreign_keys=ON、journal_mode=WAL、synchronous=FULL、busy_timeout=5000。
2. 所有 queue enqueue、payload insert/delete、admit/reserve、phase transition、terminal release、recovery mutation 经过 Admission Controller/controller.ts:987 transaction。
3. enqueueWithPayload 在 controller.ts:420-435 把 request row 与 encrypted payload 放进同一 transaction；expireQueued 在 :1188-1203 把 queue_timeout、payload delete、event 放进调用 transaction；completeLiveTurn 在 :715-748 把 provider terminal、cooldown、final outcome、payload delete、lease delete、event 放进同一 transaction。
4. process identity 与 dispatch_intent 在 controller.ts:1000-1134 同一 transaction durable；fault injection 在 insert identity 后抛错时，transaction rollback，不留下半个 identity。
5. markActive 在 controller.ts:601-609 先要求 dispatch_intent，再 active 与 payload delete 同 transaction；这让 recovery path 无法获得可重放 plaintext。
6. stale owner 必须通过 lease_id、owner_instance_id、generation fence；requireLease 在 controller.ts:1299-1304 与所有 delete/update changes===1 检查阻挡 stale mutation。

### 7.2 SQLite/process concurrency

1. Admission 在 `Admission Controller/controller.ts:386-389` 配置 WAL、FULL、busy_timeout；`SQLiteSessionStore` 在 `ACP Connector/acp/session/sqlite-store.ts:144-148` 配置相同三项，并明确依赖 SQLite cross-process writer serialization。
2. dispatch identity transaction 失败后，controller.ts:1017-1033 只在 SQLite contention 时 bounded recheck committed exact winner；不会盲目重写 prompt。
3. inspectDispatchIdentityContentionWinner 在 controller.ts:1035-1075 同时读取 lease/request/identity，只有 exact matching dispatch_intent 才返回 idempotent committed。
4. start gate 通过 lease phase count、start_history、recent reservation cutoff 共同约束；但当前没有跨 Connector policy fingerprint 或 soft-drain state。
5. local session claim 与 global Admission lease 是两层不同 fence：TurnScheduler 在 ACP session 内保证单 turn；Admission lease 在账号内保证 global seat。二者都必须成功后才进入 child prompt write。

## 0. 结论与范围

### 0.1 唯一模型结论

1. `ACP Connector` 拥有一个 ACP session 内的单 turn claim、ACP v1/v2 wire、Antigravity 进程与 conversation 数据、权限/认证/取消以及在线更新；它不拥有账号级共享席位或 Agent 生命周期。
2. `Admission Controller` 是同一 `AGY_ACP_STATE_DIR` 下所有 Connector 共享的 durable state authority，拥有 request queue、queued-owner binding、seat、lease、start gate、durable policy/drain、cooldown、payload 删除、terminal/recovery 账本、suspect/reaper 判定和 process-evidence 判定；它不导入 ACP、agy CLI、conversation SQLite 或客户端通知。
3. `PASEO_AGENT_ID` 的唯一业务语义是可信的 agent key（fairness key）；其 canonical physical/API identifier 是 `agent_id`/`agentId`。它不是 Paseo 的 `ParentAgentId`、不是账号 ID，也不表示父子 Agent 关系。
4. `recovery_required` 是“业务 prompt 可能已经发送但结果不确定”的可见、不可自动重放状态。它对自动执行是 terminal，对外部 Provider 结果不是成功或失败事实；seat 可在独立的进程退出证据成立后释放。
5. 模型保留比 Scheme 摘要更细的 dispatch 状态：`dispatch_intent`、`dispatch_ambiguous` 和 `provider_terminal` 不能折叠掉，否则会破坏 prompt 不重放与单终态不变量。live source 只部分提供这些 primitive：`ACP Connector/agy/cli.ts:1132-1142` 的生产路径已有 `prepare/beforePromptWrite/afterPromptWrite` hooks，但中间的单次 stdin 写没有产生 accepted/ambiguous 三态结果，`AgyPromptFreeDispatchBoundary` 尚无生产 call site；生产 dispatch 接线是 `SOURCE_FIELD_GAP`，不能写成已完成。

### 2.2 唯一跨区 seam

组合方向只能是：

```text
ACP session handler
  -> TurnScheduler.claim (session-local ownership)
  -> turnAdmissionAdapter
  -> AdmissionTurnCoordinator.admit
  -> AdmissionController.enqueue/admit/lease/terminal
  -> TurnDispatchBoundary (process identity + dispatch fence)
  -> existing AgyCliSession.prompt
  -> StreamPoller / Translator / conversation SQLite
  -> ACP v1/v2 session/update and typed terminal
```

live seam 是 `ACP Connector/acp/agent.ts:645-719` 的 `composeAcpRuntime`，连接 `createAdmissionRuntime`、`SQLiteSessionStore`、`AdmissionTurnCoordinator`；`ACP Connector/acp/session/prompt.ts:393-408` 将 `sessionId/model/promptText/TurnClaim` 送入 coordinator；`ACP Connector/admission/turn-coordinator.ts:299-364` 提供目标 boundary 在 prompt write 前后调用 Admission fence。`Admission Controller/` 不反向导入 ACP 实现，架构检查必须继续保持这一方向。

当前接线边界必须单独记录：`ACP Connector/agy/cli.ts:1132-1142` 的生产 `runPromptCommand` 已调用可选 boundary 的 `prepare/beforePromptWrite/afterPromptWrite` hooks，但中间的单次 stdin 写没有 accepted/ambiguous 三态结果；`AgyPromptFreeDispatchBoundary.run`（`ACP Connector/agy/dispatch-boundary.ts:119-181`）和 prompt-free process primitive 当前没有生产 call site。故“唯一 seam”是目标组合边界，生产 accepted/ambiguous 映射仍为 `SOURCE_FIELD_GAP`，不能把现有 hooks 或测试可见 primitive 当成生产完成。

下游 Feature/Contract 必须把以下 exact seam 当作最小输入输出，不得新增第二条 live output path：

- 输入：`sessionId`、`model`、`promptText`、已存在的 `TurnClaim`、progress callback、`execute(boundary)`。
- Admission 回报：`queued` observation、`AdmissionLease`、typed queue timeout/cancel/recovery/failure、或 `completed/cancelled` outcome。
- boundary：`prepare` 只接受无业务 prompt 启动的 child；process identity 与 `dispatch_intent` durable commit 后才允许在同一 turn/lease 内同步单次写入 `BUSINESS PROMPT`；Pipe 与 PTY 共享该 fence，`accepted` 之外均为 `dispatch_ambiguous`，永不 retry。permission-key PTY write 不计入该 business write。
- 输出：仍走现有 ACP notify/RPC；Admission 不建立 outbox、custom ACK、terminal replay 或第二个 SQLite-to-ACP delivery owner。

## 3. Ubiquitous language

以下术语为本仓库唯一 domain language。代码中的旧 source spelling 只可作为迁移输入或 fail-closed diagnostic 出现，不是 target domain/API term，也不是可保留的 alias。物理/API 只选 `agent_id`/`agentId`；`agent_key`/`agentKey` 明确不是 selected identifier。

| canonical term | 精确定义 | owner | 禁止替代/误读 |
| --- | --- | --- | --- |
| **turn** | 一条业务 prompt 从 admission 到明确 terminal/recovery 的一次执行尝试；一个 seat 计一个 turn | Admission（全局）；ACP（本地执行） | 不等于 session、ACP connection、Agent 或 Connector process |
| **ACP session** | ACP 客户端与 Connector 的 session/conversation 上下文，承载单 slot 顺序 | ACP Connector | 不占 seat；空闲 session 不等于 active turn |
| **conversation** | Antigravity conversation SQLite 中的 provider 对话历史 | ACP Connector/Agy DB | 不是 Admission queue 或 recovery authority |

| **agent key** | 启动时可信注入的 `PASEO_AGENT_ID`，只用于 per-agent fairness 与 eligibility grouping；canonical physical/API identifier 是 `agent_id`/`agentId` | Paseo 注入；Admission 使用 | 不是 queued-owner、parentage、账号 ID、owner process ID；不是旧 source spelling |

| **admission** | Controller 在全局 queue 中选择并创建 lease 的动作 | Admission Controller | admission 不是 process start，也不是 prompt 已发送 |
| **seat** | 账号共享池中的一个 active-turn capacity unit；`admitted/starting/dispatch_intent/dispatch_ambiguous/active/recovery_required` lease 都计入 | Admission Controller | session、connection、model、Connector 不各自拥有 seat |

| **lease fence** | `(lease_id, generation, owner_instance_id)` 三元组；所有 mutation 必须匹配 | Admission Controller | PID、request_id 单独不能替代 fence |
| **owner instance** | Connector 进程的 UUID v4 与创建时间/进程证据绑定；用于 queued-owner 与 lease ownership | ACP 提供身份；Admission 持久化/核验 | 不是 `PASEO_AGENT_ID`、PID 或 ParentAgentId |

| **dispatch intent** | 已持久化 process identity、lease fence 和“即将做唯一 `BUSINESS PROMPT` write”的事实 | Admission Controller | 不是 delivery claim 或 outbox |
| **dispatch ambiguous** | prompt write/commit/cancel 结果无法证明时的非终态不确定状态 | Admission Controller | 不得当作 `provider_failure`、success 或 retryable |
| **active** | 唯一业务 prompt 已被同步 write 接受，turn 进入原有 Agy/ACP 在线路径 | ACP 执行；Admission 计 seat | 不等于 provider 已成功 |
| **provider terminal** | Provider outcome 已明确但仍在同一事务内等待写入最终 outcome/release | Admission Controller | 不是对客户端发送的最终 success |
| **terminal** | 客户端/业务可消费的不可自动继续状态 | ACP wire + Admission durable state | `provider_terminal` 不单独算 terminal |
| **recovery_required** | prompt 可能已发送、执行或 Provider 结果不明；删除 replay payload，等待外部确认，禁止自动 replay | Admission Controller；ACP 显示 typed failure | 不得用于尚未 dispatch 且有 no-write proof 的 queued-owner death；不得改写成 completed、cancelled、provider_failure 或自动 requeue |
| **queue timeout** | request 在 `deadline_at` 前未被 admission，进入 `queue_timeout` 并删除 payload | Admission Controller | 不是 Provider timeout，不占 active seat |
| **cooldown** | `(provider, model)` 的 `not_before` eligibility fence；只过滤可启动请求 | Admission Controller | 不占 seat、不改变 FIFO、不代表 Provider 永久故障 |
| **policy consistency** | 共享 DB 的每个 enabled Connector 使用完全相同的 normalized policy tuple | Admission Controller | 不得取较大值、各算各的或静默替换 |
| **soft-drain** | 仅 `maxActiveTurns: 3 -> 1` 的运行时排空过程；保留 active turn，暂停新 admission，active count 到 0 后进入单席 | Admission Controller | 不是 cancel、SIGKILL、抢占或立即改 seat |
| **queue observation** | position、eligiblePosition、waitedMs、cooldownUntil 的只读进度 | Admission/ACP report；不改变顺序 | 不是业务消息、lease、priority override |
| **trusted-503 evidence predicate** | 只有外部证据同时绑定 provider capacity/HTTP `503`、结构化 code/reason、真实 output carrier 与 source identity 时才满足；本仓库当前未取得该证明 | 外部 evidence predicate；ACP adapter 仅在证明成立后提供，Admission 才可分类/持久化 | `result.error`、静态 phrase、`AgyCliError.message/stderr`、fake stderr、下游 classifier 输入都不能单独成为 trusted evidence |
| **PermissionDecision** | ACP client/provider 对 permission request 的选择；它与 admission、seat 和 `BUSINESS PROMPT` write 分离 | ACP Connector + ACP client | Admission 不决定 permission；permission-key PTY write 不是 business prompt dispatch |
| **account boundary** | 同 OS user + 同一 `AGY_ACP_STATE_DIR` 的共享 Admission pool；当前无可信 account ID | Admission runtime config | 换 model/多开 Connector 不能扩大 pool |

## 5. Turn lifecycle state machine

### 5.1 状态分类

| state | class | seat | payload | terminality | authoritative owner |
| --- | --- | ---: | ---: | --- | --- |
| `absent` | pre-entity | 0 | 0 | 不存在 | Admission |
| `queued` | waiting | 0 | 1（加密） | nonterminal；可 cancel/timeout | Admission；顺序由 ACP claim 先取得 |
| `admitted` | reserved | 1 | 1（直到 irreversible boundary） | nonterminal | Admission lease owner |
| `starting` | startup gate crossed | 1 | 1 | nonterminal | Admission + ACP process owner |
| `dispatch_intent` | irreversible boundary committed, write not yet performed | 1 | 1 | nonterminal；只能 active/ambiguous/recovery/confirmed pre-write terminal | Admission fence |
| `dispatch_ambiguous` | write result unknown | 1 | 0/不可重放 | nonterminal operationally；唯一自动出口是 recovery_required | Admission evidence |
| `active` | prompt write accepted, backend executing | 1 | 0 | nonterminal | ACP execution + Admission lease |
| `provider_terminal` | outcome observed, release transaction in flight | transient 1 | 0 | not client terminal | Admission transaction |
| `completed` | confirmed successful outcome | 0 | 0 | terminal success | Admission; ACP reports `end_turn` |
| `provider_failure` | confirmed typed execution/provider failure or safe pre-write failure disposition | 0 | 0 | terminal failure | Admission; ACP typed failure |
| `cancelled` | confirmed queued/pre-write/running cancellation | 0 | 0 | terminal cancellation | Admission + ACP cancel path |
| `queue_timeout` | deadline exceeded before admission | 0 | 0 | terminal timeout | Admission; ACP typed queue timeout |
| `recovery_required` | uncertain dispatch/execution or Provider outcome; payload gone | lease may be 1 until evidence release | 0 | terminal for automatic dispatch；unresolved external result | Admission; manual confirmation is outside this model |

`recovery_required` 不是“可再次尝试”的中间队列状态。只有显式新消息才能形成新的 `TurnRequest`；本版本没有 manual requeue/recovery claim authority。每个 request 只能写入一个最终 terminal；`provider_failure`、`queue_timeout`、`cancelled` 与 `recovery_required` 均不得映射为成功 `end_turn`。

### 5.1.1 ACP v1/v2 typed terminal mapping

prompt-turn terminal 的唯一物理 owner 是 `ACP Connector/acp/session/prompt.ts`。`ACP Connector/acp/terminal/index.ts` 只负责 execute-tool terminal display；`ACP Connector/acp/session/update-wire.ts` 只负责 streamed `session/update` payload conversion。

| domain terminal | v2 exact target | v1 exact target | source disposition |
| --- | --- | --- | --- |
| `completed` | exactly one `state_update{state:"idle",stopReason:"end_turn"}` | exactly one `PromptResponse{stopReason:"end_turn"}` | 既有成功路径保留 |
| `cancelled` | exactly one idle `state_update` with `stopReason:"cancelled"` | exactly one `PromptResponse{stopReason:"cancelled",_meta:{"agy-acp/turnTerminal":{version:1,code:"cancelled"}}}` | cancel 路径有 source evidence；跨进程 exactly-once 仍需 regression |
| `queue_timeout` | exactly one idle `state_update` with `stopReason:"queue_timeout"` | exactly one `PromptResponse{stopReason:"refusal",_meta:{"agy-acp/turnTerminal":{version:1,code:"queue_timeout"}}}` | current error 未完整映射；`SOURCE_FIELD_GAP` |
| `provider_failure` | exactly one idle `state_update` with `stopReason:"provider_failure"` | exactly one `PromptResponse{stopReason:"refusal",_meta:{"agy-acp/turnTerminal":{version:1,code:"provider_failure"}}}` | current v2 failure handler sends `end_turn`，v1 failure path throws；`SOURCE_FIELD_GAP` |
| `recovery_required` | exactly one idle `state_update` with `stopReason:"recovery_required"` | exactly one `PromptResponse{stopReason:"refusal",_meta:{"agy-acp/turnTerminal":{version:1,code:"recovery_required"}}}` | current error surface 未完成 mapping；`SOURCE_FIELD_GAP` |

v2 `stopReason` 是开放字符串，本轮输出集固定为 `end_turn|cancelled|queue_timeout|provider_failure|recovery_required`。已知失败不得 raw RPC throw 或映射为 `end_turn`。live source 当前的 generic failure enum 不是本模型的 target terminal name；Feature/Contract 使用 `provider_failure`。

### 5.2 规范 transitions

每一行都是一个独立 guard/effect/terminality 合同。任何未列出的 request/lease state transition 都是非法。

| from -> to | guard | atomic effects / event | terminality |
| --- | --- | --- | --- |
| `absent -> queued` | enabled；session 已有 local `TurnClaim`；request metadata 新建或 immutable metadata 完全相同；payload expiry > now；encryption/content key 可用 | INSERT `turn_requests` + AES-GCM `turn_payloads`；写 `request_enqueued`；幂等同 request 不能换 metadata/payload | nonterminal；进入 queue |
| `queued -> cancelled` | exact request 仍 queued；local claim abort/cancel/close；尚未获得 lease | 同事务 `state=cancelled`、`terminal_at`、删除 payload、写 `request_cancelled` | terminal cancellation；不得再 admit |
| `queued -> queue_timeout` | `deadline_at <= now`，仍 queued | 同事务更新 timeout、删除 payload、写 `request_queue_timed_out` | terminal queue timeout；不能 replay |
| `queued -> cancelled`（owner death） | queued-owner binding 存在；owning Connector exit 已由完整 process evidence 证明；request 尚未获得 lease/dispatch，存在 no-write proof | 同事务写 `state=cancelled`、reason/event `queued_owner_dead`、删除 payload 并移除队列占位；不得等待原 30 分钟 deadline，不得 replay；后续 eligible request 立即可选择 | terminal cancellation；exactly one `cancelled` wire terminal |
| `queued -> admitted` | Controller transaction 选择该 request；payload authenticated/present；未过期、未取消；provider/model cooldown inactive；seat capacity available；owner Connector 只能请求当前 selector 选中的 request | increment lease generation；INSERT one lease phase admitted；写 `request_admitted` | nonterminal；seat acquired |
| `admitted -> starting` | exact `LeaseFence`；phase admitted；global start count < 1；最近 start/reservation 已超过 2s；policy not soft-draining | append `start_history`；lease/request phase `starting`；写 `request_starting` | nonterminal；仍占 seat |
| `starting -> dispatch_intent` | exact fence；prompt-free child identity complete and verified；process identity + lease fence can commit in one SQLite transaction；business prompt 尚未写 | persist connector/child evidence；lease/request phase `dispatch_intent`；写 `request_dispatch_intent`；commit 后同步进入 write boundary | nonterminal；唯一 irreversible write 之前 |
| `dispatch_intent -> active` | same fence；cancellation generation/owner matches；writeInitialPrompt returns positive `accepted` synchronously；不能有 await between commit and first write | single prompt write；phase active；删除 payload；写 `request_active`；原 Agy/ACP stream path continues | nonterminal；payload no longer replayable |
| `dispatch_intent -> dispatch_ambiguous` | write not accepted/throws，或 dispatch-intent/cancellation/transaction proof 不足 | retain fenced lease；cache ambiguous result；删除/不暴露可重放 payload；写 `request_dispatch_ambiguous` where applicable | nonterminal operationally；no retry，only recovery path |
| `admitted/starting/dispatch_intent -> provider_failure` | direct proof prompt write did not occur；exact fence still valid；typed non-cancel failure disposition | same txn request terminal、删除 payload、删除 lease、write `request_abandoned` | terminal provider-failure；no replay |
| `admitted/starting/dispatch_intent -> cancelled` | same as above, but local claim/cancel is authoritative and no prompt write occurred | same as above with cancelled outcome | terminal cancellation；no replay |
| `admitted -> recovery_required` | owner/fence or process start result is uncertain before process identity; no direct no-write proof | update request recovery_required；delete payload；retain bounded recovery evidence；no replay | automatic-execution terminal；not success/failure fact |
| `starting -> recovery_required` | startup crossed but process identity is absent or cannot prove whether a business write could occur | update request/lease recovery_required；delete payload；retain seat until independent process evidence | automatic-execution terminal；not success/failure fact |
| `dispatch_intent/dispatch_ambiguous/active -> recovery_required` | prompt may have been written, Provider state unknown, heartbeat/fence failure, process ambiguity, or settlement cannot prove terminal | update request/lease recovery_required；delete payload；write `request_recovery_required`；retain seat until independent process evidence | automatic-execution terminal；not success/failure fact |
| `active -> provider_terminal` | ACP/Agy path has a typed confirmed outcome; failure category validated; exact fence still active | update request state; if `provider_capacity`, prepare/merge `(provider,model).not_before`; write `request_provider_terminal` | transient; must be consumed in same transaction |
| `provider_terminal -> completed` | outcome completed; same controller transaction owns fence | write final outcome; delete payload; delete lease; write `request_released` | terminal success; immediate seat release |
| `provider_terminal -> provider_failure` | outcome is a confirmed non-success result; category one of seven typed categories and not an unresolved trusted-503 claim | write final typed failure; delete payload; delete lease; write `request_released`; capacity cooldown only after trusted-503 predicate is externally proven | terminal failure; immediate seat release |
| `provider_terminal -> cancelled` | provider/process cancellation confirmed | write final cancellation; delete payload; delete lease; write `request_released` | terminal cancellation; immediate seat release |
| `admitted/starting/dispatch_intent/dispatch_ambiguous/active/recovery_required -> recovery_required` with seat release | connector owner not same/gone or PID reused, child gone/pid reused, process-group residue empty, all observations verifiable; exact fence still matches | preserve request as recovery_required; delete payload; delete lease; write `request_recovery_seat_released`; no provider result is invented | terminal for local capacity; external result remains unresolved |

### 5.3 Cancellation, steer, disconnect and dead-owner races

- **Queued cancel**：`TurnScheduler` claim abort plus `AdmissionController.cancelQueued` is the only direct queued cancellation. A concurrent timeout/admission may win; the losing caller must treat the fenced transaction as the authority, never issue a second terminal.
- **Running cancel**：`session/cancel` aborts the claim and asks Agy to stop. It does not directly mutate `active -> cancelled`; only confirmed execution outcome uses `provider_terminal -> cancelled`. If prompt/process outcome is uncertain, use `recovery_required`.
- **Steer**：`TurnScheduler.reserveSteer` creates a FIFO reservation before any await, aborts/displaces the current local claim, then promotes the new claim. It never bypasses global Admission and never creates a second active turn for one session.
- **Disconnect/close/delete/evict**：close local scheduler first, cancel queued items, stop Agy, and settle each global lease using the same fence. Disconnect never triggers Provider replay, terminal replay, outbox delivery, or a new request automatically.
- **Heartbeat expiry**：marks owner/lease suspicious only. It is not dead-owner proof and cannot release a seat.
- **Queued owner death**：enqueue 必须先 durable 绑定 owning Connector instance。完整 evidence 证明 owner exit 且 request 尚未获得 lease/dispatch 后，`settleQueuedOwnerDeath` 在有界时间内将 queued request 置为 `cancelled`，reason/event=`queued_owner_dead`，同事务删除 payload、移除队列占位且禁止 replay；它不等待 30 分钟，也不阻塞后续 eligible request。当前 source 没有该 binding/reaper，属于 `SOURCE_FIELD_GAP`；agent key 不是 process liveness，也不得借用 ParentAgentId。
- **Pre-identity death**：admitted/starting 在 durable process identity 之前发生 owner/process 不确定时，进入 payload-free `recovery_required` 并保留 evidence；只有完整、claim-bound 的 no-write proof 才可走有界的 pre-write terminal。缺失或 unverifiable proof 必须 retain/fail closed，绝不授权 prompt replay。
- **Active/dead owner**：dispatch_intent/active/recovery_required 的 process evidence chain 必须核验 connector owner、child identity 和 process-group residue。heartbeat expiry 只写 suspect；runtime reaper 取得完整 evidence 后，verified exit 才能在有界时间内释放 seat，不依赖 Connector restart。stale PID、missing procfs、partial record 或 PID reuse mismatch 都不能释放。

## 6. Policy、soft-drain 与 cooldown state

### 6.1 Policy state machine

Admission mode (`disabled`/`enabled`) is separate from the enabled shared capacity state. Once enabled, the canonical policy state is owned by Admission Controller and is durable/shared by every Connector in the account boundary:

```text
disabled
enabled capacity: 3
  -> soft_draining_to_1
  -> steady(max_active_turns=1)

any enabled capacity state --any Connector tuple differs--> policy_inconsistent (fail closed)
any enabled capacity state --invalid value--> config_rejected (fail closed)
```

Guards and effects:

1. `disabled -> enabled: 3` requires `AGY_ACP_ADMISSION_ENABLED` true, absolute `AGY_ACP_STATE_DIR`, valid `PASEO_AGENT_ID`, and conservative policy values. Default is `(3, 1, 2000ms, 30min, 30s)`; `maxActiveTurns` permits only `3` or `1`; `0/2/4/5/negative/non-integer/other` fail closed.
2. All Connector instances sharing the same database must compare the complete normalized tuple, not only `maxActiveTurns`. Missing, stale, malformed or conflicting consistency record is `policy_inconsistent`, so no new request/lease/start may be accepted.
3. The only capacity transition is `3 -> soft_draining_to_1 -> steady(max_active_turns=1)`. The physical policy tuple has `drain_state` values only `steady` and `soft_draining_to_1`; its terminal is `drain_state='steady' AND max_active_turns=1`. Active turn leases are not killed; while `soft_draining_to_1`, **no new admission** occurs, while queue timeout/cancel and owner recovery still operate. When `activeLeaseCount() === 0`, the durable shared state atomically becomes that terminal tuple and admits at most one new turn; `policy_drain_completed` is written in the same transaction.
4. `1 -> 3` is not an implicit runtime mutation in this model. No Connector may locally widen capacity; the durable policy owner must enforce the single forward transition model.
5. `policy_inconsistent` is not a new recovery queue. It is a startup/admission refusal and must be surfaced as typed configuration failure.

Live evidence: `Admission Controller/runtime-config.ts:27-98,101-145` parses defaults and conservative values; `Admission Controller/controller.ts:1607-1617` validates individual policies; `controller.ts:1217-1219` only reads the frozen policy for seat capacity. There is currently no durable policy state, `beginSoftDrainTo1` or cross-Connector consistency record, so F1/F2 are Stage 3 implementation contracts, not current behavior.

### 6.2 Cooldown state

`Cooldown(provider_model)` has exactly `(provider, model, not_before, updated_at)` and is owned by Admission Controller. `provider_capacity` terminal updates `not_before = max(existing, now + capacityCooldownMs)` in the same terminal transaction. A request with active cooldown is not eligible; it does not hold a seat, alter queue order, or block another provider/model.

The target trusted-503 predicate requires provider capacity/HTTP `503`, exact structured `UNAVAILABLE` or `MODEL_CAPACITY_EXHAUSTED` semantics, the real carrier and its source identity to be proven as one external evidence chain. `classifyProviderFailure` accepts structured fields (`ACP Connector/admission/errors.ts:24-76`), but that downstream function is not provenance; `failureFromAgyError` (`ACP Connector/admission/turn-coordinator.ts:366-385`) currently derives fields from free-form message/stderr. Current status is `SOURCE_FIELD_GAP+REAL_PROVIDER_REQUIRED+SOURCE_IDENTITY_UNKNOWN`; no cooldown may be justified from this path.

## 7. Process evidence 与 recovery state

### 7.1 Evidence states

`LinuxProcessIdentityState` is one of `same | gone | pid_reused | unverifiable` (`Admission Controller/process-evidence.ts:89-90`). A valid identity compares boot id, PID, start-time ticks, PID namespace inode, PPID, process group and session (`:298-312`).

| evidence state | meaning | recovery authority |
| --- | --- | --- |
| `same` | exact persisted process instance still matches | retain lease; never release |
| `gone` | exact process instance is absent | may continue child/residue checks |
| `pid_reused` | PID exists but is a different process instance | treat as original gone only with complete remaining evidence |
| `unverifiable` | malformed/partial/unreadable evidence | retain/fail closed; no release |

The release predicate is conjunctive: persisted connector owner is no longer the same and not unverifiable; child is gone or PID-reused; process-group residue is empty; the lease fence still matches. `releaseExitedRecoverySeat` deletes only the local lease and payload while retaining request state `recovery_required` (`Admission Controller/controller.ts:672-706`). It never creates a new dispatch or terminal Provider outcome.

For pre-dispatch/no-identity recovery, the only acceptable automatic evidence is a claim-bound HMAC proof binding request id, lease id/generation, recovery generation, claimant instance, connector/child identity, `owner=root=gone`, and `residue=empty` (`Admission Controller/process-evidence.ts:42-87,184-211,314-352`). The proof signer and verifier do not themselves mutate the Controller.

### 7.2 Recovery phase matrix

| phase | guard and target effect | current source disposition |
| --- | --- | --- |
| `queued` | durable queued-owner binding exists; verified owner exit plus no-write proof yields bounded `queued -> cancelled(reason=queued_owner_dead)`, deletes payload in the same transaction, removes queue blockage and never replays | no queued owner field or bounded owner settlement (`Admission Controller/schema.ts:118-135`; `controller.ts:805`); `SOURCE_FIELD_GAP` |
| `admitted` | heartbeat expiry only marks suspicion; if owner/start outcome cannot be proven before identity, enter payload-free `recovery_required`; verified exit later releases local seat | current coordinator can mark execution recovery on a heartbeat write failure, but no runtime suspect/reaper exists; `SOURCE_FIELD_GAP` |
| `starting` before identity | missing or uncertain process identity is not a no-write proof; retain recovery evidence and do not dispatch again; release only after a complete verified-exit predicate | startup recovery retains null identity, but this is startup-only (`ACP Connector/admission/startup-recovery.ts:62-68`); runtime path missing |
| `starting` after identity / `dispatch_intent` | process evidence and lease fence decide; ambiguous write deletes payload and enters `recovery_required`; verified connector/child exit plus empty residue releases seat without restart | existing hooks bracket one stdin write, but production lacks accepted/ambiguous three-state mapping (`ACP Connector/agy/cli.ts:1132-1142`); production `SOURCE_FIELD_GAP` |
| `active` | heartbeat expiry is suspicion only; uncertain provider/process outcome stays `recovery_required` and payload-free; reaper obtains process evidence and releases only verified exit | startup recovery covers persisted dispatches; no runtime reaper; `SOURCE_FIELD_GAP` |
| `recovery_required` | remains terminal for automatic execution and never requeues; runtime reaper may delete only the local lease after conjunctive verified-exit evidence | `recoverExitedAdmissionSeats` is invoked at startup (`ACP Connector/admission/runtime.ts:68`); no no-restart bounded runtime loop |

The runtime reaper is an Admission-owned process-evidence consumer, not a second delivery path. It must cover all rows above, preserve uncertain execution as payload-free `recovery_required`, and make a verified exit release seat in bounded time without requiring Connector restart.

### 7.3 Current recovery reachability

`createAdmissionRuntime` calls `recoverExitedAdmissionSeats` at startup (`ACP Connector/admission/runtime.ts:48-80`). The current function enumerates nonterminal leases, retains null/unverifiable identity, checks connector/child/process-group evidence, and either marks recovery or releases a proven-exited seat (`ACP Connector/admission/startup-recovery.ts:41-105`). Heartbeat failure in `AdmissionTurnCoordinator.admit` marks execution recovery rather than freeing capacity (`ACP Connector/admission/turn-coordinator.ts:153-180`). This proves only the existing startup path; it does not prove queued-owner, pre-identity, production dispatch, or runtime reaper coverage.

The model requires a bounded **runtime** recovery pass for repeated `recovery_required` cases without Connector restart; current source has only startup recovery. This remains `SOURCE_FIELD_GAP` owned by the Admission recovery seam, not permission to claim that restart-based recovery satisfies the Scheme.

## 8. Transaction 与 concurrency invariants

These are domain invariants. A Stage 3 implementation or Contract may add physical machinery only when it proves one of them; it may not introduce a new delivery authority to simulate them.

1. **One durable admission authority**：one shared SQLite state directory is the source of truth for queue, seat, lease, start gate, cooldown, encrypted payload, terminal and recovery evidence. Current controller opens WAL + `synchronous=FULL` + foreign keys + busy timeout (`Admission Controller/controller.ts:379-390`).
2. **Schema evolution is forward-only**：current schema guard is v1 structural evidence (`Admission Controller/schema.ts:101-255,261-291`), not the target physical contract. Stage 3 SHALL perform one forward v2 migration for canonical `agent_id`, shared policy/drain state, queued-owner binding and recovery/suspect evidence; exact tables, columns, indexes and constraints belong to the architecture/physical contract. Unexpected outbox/claim/replay authorities remain rejected.
3. **Request/payload atomicity**：enqueue request and encrypted payload are one transaction; duplicate request metadata must match; different content fingerprint raises conflict. Cancel/timeout/irreversible write/terminal/recovery each delete replayable payload at its authoritative boundary.
4. **One request, at most one lease and one queued owner**：`leases.request_id` is unique; one lease has one generation and owner instance. At enqueue, exactly one owning Connector instance is durably bound to the request; `turn_requests.state` and `leases.phase` must agree for recoverable rows. The queued-owner binding is not a lease and cannot grant a second dispatch.
5. **Fence every mutation**：generation + owner instance + lease id is checked for admission, start, dispatch, heartbeat, terminal and recovery. A stale winner cannot issue a second dispatch or terminal.
6. **Seat accounting**：active capacity counts `admitted`, `starting`, `dispatch_intent`, `dispatch_ambiguous`, `active`, and `recovery_required` leases (`controller.ts:1207-1218`). `completed/provider_failure/cancelled/queue_timeout` have no lease.
7. **Admission order**：selection is oldest eligible plus idle-agent fairness; connector-specific `admitRequest` returns a lease only when the Controller selected that exact request. Cooldown changes eligibility only.
8. **Start gate**：at most one `admitted/starting/dispatch_intent` start at a time and starts are at least 2 seconds apart (`controller.ts:552-571,1221-1237`). No parallel start is introduced by multiple Connector processes.
9. **Single session slot**：one `TurnScheduler` has at most one active claim; steer reservations are FIFO and exist before await; release is idempotent. Local claim must precede global enqueue, preventing same-conversation concurrent writes (`turn-scheduler.ts:139-238`).
10. **Irreversible boundary is synchronous and permission-separated**：process start contains no `BUSINESS PROMPT`; in the same turn/lease, identity, cancellation fence and dispatch intent commit precede one synchronous Pipe or PTY business write; permission-key PTY writes, permission RPC and spawn are not business dispatch. Any non-positive/throwing business write is ambiguous and never retried (`ACP Connector/agy/dispatch-boundary.ts:111-181`). Production wiring is still a source gap (`ACP Connector/agy/cli.ts:1132-1142`).
11. **Heartbeat is observation**：heartbeat updates are fenced; failure changes confidence, not capacity. No timer may directly delete a lease.
12. **Terminal exactly once**：Provider terminal, final outcome, payload deletion, cooldown update only when the trusted predicate is satisfied, and lease release are one Controller transaction (`controller.ts:708-749`). A late cancel/heartbeat/error loses by fence and cannot append another final state. The model requires one `completed`, `cancelled`, `queue_timeout`, `provider_failure` or `recovery_required` terminal; current source does not prove the absence of every cancel double-terminal race.
13. **Recovery is no replay**：uncertainty after a possible dispatch deletes payload and becomes visible `recovery_required`; queued owner exit before lease/dispatch is a bounded payload-free `cancelled(reason=queued_owner_dead)` terminal; proven local process exit for an uncertain dispatched turn may release capacity but cannot change that request into success/provider_failure/cancelled or requeue it. Runtime reaping must work without Connector restart.
14. **Queue observation is pure**：progress notifications are best-effort and cannot change order, priority, state, lease or terminality (`turn-coordinator.ts:267-286`).
15. **Policy consistency precedes mutation**：all connectors must agree on the same policy before queue/lease operations; no max/min merge, silent replacement or independent pool.
16. **Legacy isolation**：when Admission is disabled, `composeAcpRuntime` leaves legacy JSON/session and prompt path untouched (`ACP Connector/acp/agent.ts:641-719`). Enabled mode still uses the one online ACP update path.
17. **No cross-layer authority leak**：ACP may report process/provider observations; only Admission commits global state. Admission cannot emit ACP client notifications or decide `PermissionDecision`/UI outcomes.
18. **Trusted evidence is not inferred**：generic `result.error`, static phrases, `AgyCliError.message/stderr`, fake stderr and downstream classifier inputs do not satisfy the external trusted-503 predicate. Current status remains `SOURCE_FIELD_GAP+REAL_PROVIDER_REQUIRED+SOURCE_IDENTITY_UNKNOWN`.

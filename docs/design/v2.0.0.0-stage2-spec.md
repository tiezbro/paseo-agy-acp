## 0. Problem Statement

Antigravity ACP Connector 当前需要在同一账号的本地使用范围内承载多个 Paseo Agent 的 turn，但当前能力边界存在四类风险：共享席位、排队与启动节流必须跨 Connector 原子一致；一个业务 prompt 的第一次不可逆写入必须有可验证的 dispatch fence；进程、heartbeat、取消和 Provider 终态竞态不能造成重复执行或永久丢席；ACP 的既有 session、permission、conversation、history 与在线通知路径不能被第二套 delivery authority 取代。

成功结果是：默认共享池最多 3 个活动 turn，唯一保守整体 override 为 1；请求按 oldest-eligible 与 `PASEO_AGENT_ID` fairness 排队；相邻启动至少 2 秒且全局同一时刻最多一个 start；队列、payload、lease、policy、cooldown、终态和 recovery evidence 由一个 durable state authority 支撑；无法确认 prompt 是否已发送时，payload 被删除、状态可见为 `recovery_required`、永不自动重放。

成功结果不是官方 503 永远消失，也不是通过字符串猜测把任何 overload 文本当作 capacity。trusted 503 的来源链当前仍是外部 typed dependency：`SOURCE_FIELD_GAP` + `REAL_PROVIDER_REQUIRED` + `SOURCE_IDENTITY_UNKNOWN`。这三项合并为一个外部 disposition，不是内部规格歧义。

## 3. User Stories

1. 作为同时使用多个 Paseo Agent 的操作者，我希望同一 Antigravity 账号最多执行 3 个 turn，从而避免并发主动放大 Provider 故障。
2. 作为需要保守运行的操作者，我希望把整个共享池降为 1，并让已有 turn 自然结束，而不是杀死 active turn。
3. 作为配置维护者，我希望 `2`、`4`、`5`、`0`、负数、非整数和其他非法席位值 fail closed，从而不出现 Connector 各自计算容量的情况。
4. 作为排队用户，我希望未占席的 agent 优先、同一优先层按 oldest-eligible 排序、同一 session 保持单 turn 顺序。
5. 作为排队用户，我希望 cooldown、取消、超时和 owner 消失不会挡住后续 eligible request。
6. 作为用户，我希望排队最多 30 分钟，超时后 payload 与 timeout terminal 同事务处理，并且旧 prompt 不会在很久以后执行。
7. 作为用户，我希望 Provider 明确终态或本地明确失败后立即释放席位，空闲 session/connection 不占 seat、不驻留 turn process。
8. 作为用户，我希望 Connector 无法确认 prompt 是否已经发送时删除可重放 payload、公开 `recovery_required`，而不是自动重试。
9. 作为多账号操作者，我希望账号使用独立 `AGY_ACP_STATE_DIR`，并在换号前排空、停机，避免旧账号请求落入新账号。
10. 作为 ACP 用户，我希望 Admission 开启时仍保留既有 permission/client notification/history/cancel 链，只有第一次不可逆业务 prompt write 受 Admission fence 约束。
11. 作为 Paseo 顶层 Controller，我希望 Paseo 继续拥有 Agent 生命周期，MAACS 继续在仓库外拥有路由/health，`paseo-agy-acp` 不创建第二套 supervisor、ledger 或 runtime synchronizer。

## 5. Normative State And Invariants

### 5.1 Request and lease states

`RequestState` 的目标全集固定为：`queued`、`admitted`、`starting`、`dispatch_intent`、`dispatch_ambiguous`、`active`、`provider_terminal`、`completed`、`failed`、`cancelled`、`queue_timeout`、`recovery_required`。`provider_terminal` 是写 final outcome/release 的事务内过渡；最终客户端 terminal 只出现一次。

| Transition | Guard | Atomic effects | Outcome |
| --- | --- | --- | --- |
| enqueue -> `queued` | enabled runtime、valid request、owner binding、payload expiry valid | request row + encrypted payload + queued-owner binding in one transaction | eligible queue item |
| `queued` -> `queue_timeout` | `now >= deadline_at` | state, terminal time, timeout event, payload delete in one transaction | exactly one `queue_timeout` terminal; no lease |
| `queued` -> `cancelled` | exact queued request cancellation or verified queued-owner death settlement | state, reason event, payload delete in one transaction | exactly one `cancelled` terminal; no dispatch |
| `queued` -> `admitted` | oldest-eligible selector, no drain/cooldown, owner fence matches | lease row + generation + admission event | one seat reserved |
| `admitted` -> `starting` | global start count zero and last start at least 2,000 ms ago | phase and start history | one start reservation |
| `starting` -> `dispatch_intent` | connector/child identity recorded and dispatch intent commit succeeds | process identity + intent transaction | write may occur on same synchronous stack |
| `starting` -> `failed`/`cancelled` | no-write proof and explicit local failure/cancel | terminal + payload delete + lease release | no replay |
| `dispatch_intent` -> `active` | first business write returns accepted | payload delete + active phase | one irreversible write, one active seat |
| `dispatch_intent` -> `dispatch_ambiguous` | cancellation fence, intent commit, write or accepted result is not provable | ambiguous event; no second write | immediately proceeds to recovery-required settlement |
| `dispatch_ambiguous`/`active` -> `recovery_required` | provider/local outcome is uncertain or owner/process evidence is insufficient | payload delete, recovery event, no retry | visible failure terminal, local release only after evidence rule |
| `active` -> `provider_terminal` -> final | one provider/local terminal and matching lease fence | final outcome, optional independent failure classification, cooldown only for trusted capacity, payload already absent, lease delete in one transaction | exactly one terminal and immediate seat release |
| `recovery_required` -> local released | old connector gone, child gone or PID reused, process group/descendants empty, evidence not unverifiable | release local lease, recovery-seat-released event; state remains recovery_required | no seat leak, no claim of remote outcome |

### 5.2 Invariants

1. At most `max_active_turns` leases are active globally; 3 is default, 1 is the only whole-pool override.
2. `max_concurrent_starts = 1`; every consecutive start is separated by at least 2,000 ms.
3. A session has at most one local `TurnClaim`; a request cannot bypass the global selector by waiting on its own id.
4. Fairness uses `agent_id` from `PASEO_AGENT_ID`; idle agents are eligible before agents with an active turn, then `enqueued_at ASC, request_id ASC`.
5. A queued request is eligible only when state, deadline, cooldown, drain state and owner evidence allow it. A cancelled, timed-out, dead-owner or verified released request cannot block another eligible request.
6. A payload is encrypted at rest and deleted at queue timeout, cancellation, no-write terminal, accepted first write, provider terminal, recovery settlement and session-close cancellation. No readable payload remains after uncertainty.
7. Every business prompt has zero or one write attempt. `accepted` is the only result that proves active; `blocked` and `dispatch_ambiguous` never retry.
8. `heartbeat` is liveness observation only. Expiry sets suspicion metadata; it never releases a seat without connector/child/process-group/descendant/PID-reuse evidence.
9. A stale owner cannot mutate a lease because request id, lease id, generation and owner instance fence must all match.
10. A terminal is idempotent at the durable fence and emitted exactly once to ACP. Failure is never serialized as successful `end_turn`.
11. Idle ACP session/connection has zero Admission lease and zero resident turn process.
12. `sessions` is ACP session persistence inside the same physical file but is not an Admission seat ledger; Admission never writes conversation/session semantic columns.
13. Unknown provider text is discarded before durable classification. `429`, auth, permission, timeout and transport remain independent and never open capacity cooldown.
14. The sole online output route remains `AgyCliSession.prompt` -> conversation SQLite -> `StreamPoller`/`Translator` -> ACP client updates.

### 5.3 Policy state machine

The normalized policy tuple is:

```text
(max_active_turns, max_concurrent_starts, min_start_interval_ms,
 queue_timeout_ms, capacity_cooldown_ms)
```

Defaults are `(3, 1, 2000, 1800000, 30000)`. `max_active_turns` accepts only `3` or `1`; `max_concurrent_starts` accepts only `1`; `min_start_interval_ms >= 2000`; `0 < queue_timeout_ms <= 1800000`; `capacity_cooldown_ms >= 30000`. Every malformed, non-integer, negative, zero where forbidden, unsafe or out-of-bound override fails closed before runtime creation. An explicit `3` is normal mode; `1` is the only whole-pool conservative mode. The global start contract is one start at a time with a minimum `2s` interval.

The canonical transition is exactly:

```text
steady(max_active_turns=3)
  -> beginSoftDrainTo1
  -> soft_draining_to_1
  -> activeLeaseCount() === 0
  -> steady(max_active_turns=1)
```

`beginSoftDrainTo1(owner, now)` atomically checks the current durable policy, sets `drain_state='soft_draining_to_1'`, writes `policy_drain_started`, rejects all new admissions, leaves queued requests queued, and does not kill active turns. The zero-active check `activeLeaseCount() === 0` and final write atomically set `drain_state='steady'`, `max_active_turns=1`, `updated_by_owner_instance_id`, and `policy_drain_completed`. `drain_state` has only `steady` and `soft_draining_to_1`; `steady(max_active_turns=1)` is the required terminal tuple. Calling the transition on an already steady one-seat policy is an idempotent no-op. No Connector may locally widen, merge, take max/min, or ignore this state.

Every opener computes the same canonical policy fingerprint using the Admission purpose key and the exact normalized tuple. First opener atomically claims the singleton `policy_state`; later openers must match tuple and fingerprint or fail closed before accepting work. Policy mismatch is not resolved by selecting the larger capacity.

## 7. Features

### F1. Shared Capacity Policy And Soft Drain

- **Business result:** every enabled Connector observes one account-wide policy, admits no more than 3 active turns by default, and can move the whole pool to one seat without killing active work.
- **Inputs/outputs:** input is validated env policy plus durable singleton; output is normalized policy projection, admission decision, drain state and policy events.
- **State invariants:** values and ranges in §5.3; singleton fingerprint equality; one global start; drain state exactly `steady` or `soft_draining_to_1`; no new lease during drain; active leases survive; zero-active completion is atomic.
- **Failure boundary:** malformed env, SQLite unavailable, schema mismatch or policy fingerprint mismatch fails closed before request admission. A non-owner or stale generation cannot transition policy.
- **Assurance:** parser regression; cross-process policy mismatch; soft-drain timeline with 3 active, queued request, zero-active barrier and second opener observation.
- **Release impact:** high; enabled runtime behavior and schema v2 change. Disabled runtime has no release impact and must remain legacy-compatible.
- **Write/conflict/resource boundary:** owns `policy_state`, policy journal events and Admission policy methods; conflicts with any other Admission schema/policy writer; uses one SQLite writer transaction and no ACP output resource.
- **Dependencies:** F7 schema migration, owner identity and Admission runtime composition.
- **Integration barrier:** no downstream task may claim shared capacity until schema v2 and policy consistency are green.
- **Residual ambiguity:** 0 internal; external trusted-503 is not a policy ambiguity.

### F2. Fair Durable Queue And Payload Lifecycle

- **Business result:** each session message enters one encrypted queue, selection is oldest-eligible with per-agent fairness, and stale/dead work cannot block later eligible work.
- **Inputs/outputs:** input is a `TurnClaim`, `sessionId`, `model`, text, canonical `agentId`, owner instance and deadline; output is queue progress, one lease or one typed queue terminal.
- **State invariants:** local session claim first; `agent_id` from `PASEO_AGENT_ID`; idle-agent preference; same-agent FIFO; request/owner identity fences; 30-minute maximum queue wait; payload DELETE in timeout/cancel/dead-owner transaction.
- **Failure boundary:** duplicate request with different payload is `PayloadConflictError`; expired payload is deleted and cannot be read; owner death settles without waiting to timeout and without replay.
- **Assurance:** queue/timeout/owner-crash/fairness matrices; cross-process SQLite contention; payload crypto and no-plaintext event scans.
- **Release impact:** high for enabled mode and v2 schema; disabled mode does not create this queue.
- **Write/conflict/resource boundary:** owns `turn_requests`, `turn_payloads`, queue indexes and owner references; does not write `sessions`, client notifications or permission state; serializes with policy and lease writes in `runtime.sqlite`.
- **Dependencies:** F1 policy, F7 migration, F3 lease interface.
- **Integration barrier:** no dispatch begins until the request is selected by the global controller and the owner fence matches.
- **Residual ambiguity:** 0 internal.

### F3. Lease, Start Gate And Business Dispatch Fence

- **Business result:** a selected request starts at most once, after durable identity/intent fencing, and the business prompt has at most one write attempt with an accepted/blocked/ambiguous outcome.
- **Inputs/outputs:** input is `AdmissionLease`, owner/process evidence, `TurnClaim`, prompt channel and text; output is `active`, `blocked` or `dispatch_ambiguous`, followed by one terminal/recovery settlement.
- **State invariants:** `prepare -> beforePromptWrite -> one business write -> afterPromptWrite`; Pipe production uses `AgyPromptFreeDispatchBoundary.run`; accepted maps to `markActive`; blocked/ambiguous maps to `markDispatchAmbiguous`/recovery; `writeAttempts <= 1`; no await between dispatch-intent commit and first write.
- **Failure boundary:** process identity unavailable, stale fence, cancellation race, uncommitted intent, fresh PTY not certified or write result not accepted all fail closed; uncertain write is never retried.
- **Assurance:** dispatch fault-point regressions; fake native process; production wiring RED/GREEN; native Pipe+EOF/signal/descendant matrix.
- **Release impact:** critical for enabled production prompt path; high blast radius for `AgyCliSession.prompt` and `runPromptCommand`.
- **Write/conflict/resource boundary:** owns request-scoped Admission fence and ACP process boundary; cannot own Provider output, permission decision or outbox; conflicts with native child spawn and cancellation resources.
- **Dependencies:** F1/F2 leases, process evidence, ACP `AgyAdmissionDispatchBoundary`.
- **Integration barrier:** production `runPromptCommand` must consume the existing prompt-free primitive before full-chain acceptance.
- **Residual ambiguity:** 0 internal.

### F4. ACP Session, Permission And Legacy Output

- **Business result:** enabled Admission keeps ACP v1/v2 session, permission, cancellation, history and online output behavior while routing the first business write through the existing fence.
- **Inputs/outputs:** input is ACP RPC/session/client permission response; output is existing `session.update`, permission RPC, conversation persistence and exactly one typed terminal.
- **State invariants:** `TurnScheduler` remains session-local authority; `PermissionDecision` remains ACP/client-owned; permission-key PTY write is not business write; Pipe and interactive PTY use the same business fence; disabled path is byte-for-behavior legacy.
- **Failure boundary:** enabled v1/v2 login/logout reject typed before provider login; non-skip permission modes cannot be rejected merely because Admission is enabled; disabled auth remains unchanged.
- **Assurance:** auth gate, permission path, queue-steer, ACP server, session store and runtime wiring receipts.
- **Release impact:** high protocol compatibility impact; no second output path and no history rewrite.
- **Write/conflict/resource boundary:** owns ACP files and conversation SQLite `sessions` rows; does not write Admission tables directly; permission PTY and child process resources are Connector-owned.
- **Dependencies:** F3 fence, F7 shared file schema, existing ACP SDK.
- **Integration barrier:** typed terminal contract must be accepted before broad ACP validation.
- **Residual ambiguity:** 0 internal.

### F5. Failure Isolation, Cooldown And Typed Terminal

- **Business result:** independently classified failures never masquerade as success; only trusted capacity evidence can affect provider/model eligibility, and every failure has one visible typed terminal.
- **Inputs/outputs:** input is a structured provider/local outcome; output is `ProviderFailureCategory`, optional cooldown mutation, terminal metadata and released seat.
- **State invariants:** categories are `provider_capacity`, `quota`, `auth`, `permission`, `timeout`, `transport`, `unknown`; 429/auth/permission/timeout/transport never create capacity cooldown; only confirmed success is `end_turn`.
- **Failure boundary:** free text, generic `result.error`, static binary phrase, fake stderr or missing source identity fail closed as non-capacity and keep the external typed stop open.
- **Assurance:** structured classifier regression and negative cooldown matrix; typed terminal RED/GREEN uses 429/transport, never unresolved 503.
- **Release impact:** high ACP wire impact; trusted-503 branch has no Stage 3 ready implementation.
- **Write/conflict/resource boundary:** ACP maps terminal; Admission owns cooldown/lease transaction; no provider output or client route replay.
- **Dependencies:** F3 terminal settlement, F4 wire, external trusted-503 evidence.
- **Integration barrier:** S3-T08 remains typed blocked and is excluded from READY calculations until separately authorized evidence exists.
- **Residual ambiguity:** 0 internal; external composite blocker is explicit and typed.

### F6. Recovery, Reaper And No-Replay Safety

- **Business result:** queued, admitted, starting, dispatch-intent, active and `recovery_required` owner loss is handled in bounded runtime/startup paths without replay or permanent seat debt.
- **Inputs/outputs:** input is heartbeat and process evidence; output is suspect metadata, bounded terminal/recovery settlement, local lease release only with full exit proof, and sanitized events.
- **State invariants:** heartbeat expiry only marks suspect; connector/child identity, process group, descendants and PID reuse all participate; `same`/`unverifiable` retains; gone/pid_reused plus empty group may release local seat; recovery state remains visible.
- **Failure boundary:** incomplete inventory, same connector, unverifiable procfs, live descendant or stale fence retains state; no restart requirement and no time-only release.
- **Assurance:** PID reuse, startup recovery, runtime reaper, three recovery-required seats and race matrices.
- **Release impact:** high operational safety impact; no external provider claim is made.
- **Write/conflict/resource boundary:** owns `suspect_*`, reaper transitions, owner evidence and recovery events; does not own ACP terminal emission or manual recovery claims.
- **Dependencies:** F2 owner binding, F3 process identity, F5 terminal settlement, F7 schema.
- **Integration barrier:** runtime reaper must be verified without restarting Connector before canary.
- **Residual ambiguity:** 0 internal.

### F7. Schema, Account Isolation And Compatibility

- **Business result:** one v2 forward schema supports policy, queue owner and recovery evidence while retaining the canonical `sessions` layout and fail-closed compatibility.
- **Inputs/outputs:** input is v1 database and SQLite version; output is exact v2 schema or typed `AdmissionMigrationError`/`SchemaIntegrityError` with v1 unchanged.
- **State invariants:** `ADMISSION_SCHEMA_VERSION=2`; one `parent_id -> agent_id` RENAME; no downgrade; `turn_requests.foreignKeys=[]`; owner id is a value reference; sessions unchanged; unexpected tables rejected.
- **Failure boundary:** SQLite <3.25 or any DDL/guard/fingerprint error stops before/within migration, leaves v1 unchanged, and never creates a partial compatibility state; v1 Connector rejects v2 DB.
- **Assurance:** schema shape, migration, contention, rollback/fault, key-store, session layout and unexpected-table tests.
- **Release impact:** high for enabled runtime; disabled runtime remains v1 legacy behavior until explicit opt-in v2 acceptance.
- **Write/conflict/resource boundary:** owns Admission schema/migrations/key file; `SQLiteSessionStore` owns only `sessions` row semantics; no second DB or migration framework.
- **Dependencies:** all Admission features; no source feature may add a table/column without a mapped invariant.
- **Integration barrier:** schema validation and cross-process fault/security stage precede native and full-chain acceptance.
- **Residual ambiguity:** 0 internal.

## 8. Cross-Feature Contracts

Contracts exist only where a real boundary crosses feature ownership. Internal details without a cross-feature relationship remain inside their Feature.

### C1. Composition And Admission API Contract (F1/F2/F3/F4)

**Owner/direction:** `ACP Connector` calls typed Admission APIs through the Connector adapter; `Admission Controller` owns durable outcomes and never calls ACP.

**Exact seam:** `composeAcpRuntime(options)` parses enabled/disabled config, creates one `AdmissionController`, performs startup recovery, opens `SQLiteSessionStore` on the same database, constructs `AdmissionTurnCoordinator({ controller, agentId })`, and returns composed options plus idempotent close. Enabled mode rejects alternate state/delivery owners. Disabled mode returns the original options and no Admission store.

**Exact call contract:**

```text
TurnScheduler.claim
  -> AdmissionTurnCoordinator.admit({sessionId, model, promptText, claim, reportProgress, execute})
  -> enqueueWithPayload({requestId, sessionId, agentId, fingerprint, provider, model, now}, prompt, expiresAt)
  -> admitRequest(requestId, now, ownerInstanceId)
  -> markStarting(lease, now)
  -> recordProcessIdentity(record)
  -> commitDispatchIntent(record)
  -> markActive(lease, now) OR markDispatchAmbiguous(lease, now)
  -> completeLiveTurn(lease, now, outcome) OR markExecutionRecoveryRequired(lease, now)
```

The request cannot self-admit, bypass fairness, or mutate raw SQL. Queue progress is a read-only callback. A closed coordinator rejects new work. `ownerInstanceId`, `agentId`, request id, timestamps, model and prompt must pass identifier/clock validation.

**API result/error contract:** `AdmissionQueueTimeoutError` maps to typed `queue_timeout`; `AdmissionTurnRecoveryRequiredError` maps to typed `recovery_required`; cancellation returns typed `cancelled`; provider/local failures carry typed category; stale fence, invalid state, migration and policy mismatch fail closed. No error path emits a successful `end_turn`.

### C3. Event And Terminal Contract (F3/F4/F5/F6)

The audit allowlist is the existing request transition set plus exactly `policy_claimed`, `policy_drain_started`, `policy_drain_completed`, and `queued_owner_dead`. Events contain only sequence, allowlisted kind, state pair, time and correlation HMAC. They contain no request id, session id, payload, raw provider text, owner identity or client route and are never delivery acknowledgements.

ACP v1 and v2 use the existing online output path and emit exactly one terminal per turn. The sole prompt-turn terminal owner is `ACP Connector/acp/session/prompt.ts`; `ACP Connector/acp/terminal/index.ts` remains execute-tool terminal display only and `ACP Connector/acp/session/update-wire.ts` remains streamed `session/update` payload conversion only. The required failure set is `queue_timeout/cancel/provider_failure(429/transport)/recovery_required`, with each outcome represented by exactly one typed terminal:

| Business outcome | terminal code | success `end_turn` allowed? | seat |
| --- | --- | --- | --- |
| provider/local success | `end_turn` | yes, only here | release immediately |
| user cancel or queued owner death before dispatch | `cancelled` with typed reason | no | release immediately |
| queue deadline | `queue_timeout` | no | no lease / release |
| provider failure (including 429 or transport) | `provider_failure` + category | no | release immediately |
| uncertain dispatch/execution | `recovery_required` | no | release after full exit evidence; state remains visible |

For v2, each turn emits exactly one idle `state_update`; its open-string `stopReason` output set for this change is `end_turn|cancelled|queue_timeout|provider_failure|recovery_required`. For v1, each turn returns exactly one `PromptResponse`: success uses `stopReason:"end_turn"`; cancel uses `stopReason:"cancelled"` plus `_meta["agy-acp/turnTerminal"]={version:1,code:"cancelled"}`; `queue_timeout`, `provider_failure`, and `recovery_required` use `stopReason:"refusal"` plus the same typed-meta object with the matching code. A known failure raw RPC throw is not the terminal contract. A failure handler must not call `emitTerminal("end_turn")`. Queue progress is not terminal. A duplicate completion observes the durable fence and emits nothing additional.

### C4. Permission And Business-Write Contract (F3/F4)

`PermissionDecision` remains owned by ACP/client through existing v1/v2 `session/request_permission`, `onPermission`, and PTY key exchange. Admission does not store permission decisions, choose mode, or count permission-key writes as business dispatch.

The sole business fence is the existing `AgyAdmissionDispatchBoundary` implemented by `TurnDispatchBoundary`:

```text
prepare(child identity)
  -> beforePromptWrite()
  -> exactly one business prompt write + EOF
  -> afterPromptWrite()  // markActive, payload already deleted atomically
```

`beforePromptWrite` fails closed when claim, generation, owner or durable state is stale. `afterPromptWrite` cannot be called twice. Removing the current enabled-mode forced `dangerously-skip-permissions` guards is mandatory; `default`, `accept-edits`, `plan`, and `dangerously-skip-permissions` remain valid modes. The interactive permission panel must be reachable in enabled mode. PTY permission-key writes happen before the fenced business write and remain ACP/client-owned.

For Pipe prompt-free production, `AgyPromptFreeDispatchBoundary.run` is the only accepted boundary and returns exactly:

```text
{ state: "active", writeAttempts: 1 }
{ state: "blocked", reason: ..., writeAttempts: 0 }
{ state: "dispatch_ambiguous", writeAttempts: 0 | 1 }
```

The boundary sequence is spawn with no business prompt in argv/environment, capture identity, persist identity, recheck cancellation/generation/owner, commit dispatch intent, synchronously call `writeInitialPrompt`, and return. `active` maps to `markActive`; `blocked` and `dispatch_ambiguous` map to `markDispatchAmbiguous`/recovery. A returned Promise is not a durability proof. `writeAttempts <= 1` (`writeAttempts<=1`); no retry or replay. Fresh prompt-free PTY is blocked unless its version-specific canary returns `verified`; the default production Pipe is stdin.

### C5. Process, Physical And Recovery Contract (F3/F6)

The evidence tuple for both connector and child is `boot_id + pid + start_time_ticks + pid_namespace_inode + ppid + pgrp + session`. PID presence alone, PID absence alone, heartbeat age alone, or an unverifiable `/proc` read is insufficient. `same`, `gone`, `pid_reused`, and `unverifiable` are distinct observations.

Heartbeat is written every 2,000 ms in the coordinator. A lease becomes suspect only when the deterministic reaper observes `now - heartbeat_at > 4,000 ms`; suspicion writes `suspect_since` and `suspect_reason='heartbeat_expired'` but never releases. Process evidence may add `identity_unverifiable`; it also never releases.

`reapSuspects(now, readers)` is bounded and idempotent. It covers queued owner instances, admitted leases, starting-before-identity, starting/dispatch-intent after identity, active leases and `recovery_required` leases. The only local seat-release proof is: old connector is not `same`/`unverifiable`, child is `gone` or `pid_reused`, and the expected process group/descendant inventory is `empty` rather than `unverifiable`. A verified release retains `recovery_required` when the business prompt may have crossed the boundary and deletes payload. Three `recovery_required` events therefore restore local capacity without restart and without claiming remote success.

Queued owner death has no child dispatch: owner evidence is durably bound at enqueue; verified owner exit settles the queued request as `cancelled` with reason `queued_owner_dead`, deletes payload in the same transaction, writes the event and removes it from eligibility. An admitted/starting request with an explicit no-write proof settles as `failed` or `cancelled` according to the local cause; any uncertain write is `recovery_required`. No path waits for the 30-minute timeout merely because the owner vanished.

Pipe uses stdin write followed by EOF. SIGTERM/SIGINT is the bounded cooperative cancellation path; SIGKILL or child error without a complete no-write proof is ambiguous and never retried. Process-group/descendant cleanup and PID-reuse evidence are part of settlement, not a second recovery authority.

### C6. Account/Auth/Legacy Contract (F1/F4/F7)

Admission enabled requires `AGY_ACP_STATE_DIR` absolute, `PASEO_AGENT_ID` valid, and one account state directory. v1 `authenticate`/`logout` and v2 `auth/login`/`auth/logout` fail closed with typed Admission-enabled errors; disabled mode preserves the existing auth behavior. Changing accounts requires stop receiving, drain/cancel queued work, finish/settle active work, stop Connector, then start a separate state directory. Login is never used to infer or merge pool identity.

The enabled runtime may share the physical file with `SQLiteSessionStore`, but only Admission owns Admission schema and only Connector owns `sessions` row semantics. Legacy JSON store, legacy permission path, legacy cancel/history and disabled prompt path remain unchanged.

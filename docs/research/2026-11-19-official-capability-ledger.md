## 建议的验收顺序

1. 先回归已验收短路径：真实新建、冷恢复、模型+档位切换、文本正文、stdio MCP、PDF resource_link、取消；每项同时对照官方原版与适配器原始帧。
2. 认证：临时 HOME 核对四种 `authMethods` 与 logout 后 -32000，再做真实个人 OAuth 和 API key 的新建；不把 `authenticate` 成功当账号可用。
3. 会话生命周期：`session/new` → `session/load`（检查历史不重复渲染）→ `session/resume`（不重放）→ `session/list`（cursor 忽略、标题固定）→ 导入。
4. 配置：model family 切换后的 thinking 保留/就近、`config_option_update` 自动替换、未知 mode 的 -32602。
5. 交互：`Default`/`Auto Edit`/`YOLO` 下的工具 permission、deny、ask_question 单选、workspace trust/hook；确认只有 `YOLO` 全自动。
6. 输入：image、audio、embedded context、resource_link 各一次；记录官方消费、静默丢弃与后端拒绝三种结果。
7. 输出与计量：thought 帧、tool start/end、`usage_update` 的 used/size、`PromptResponse.usage`、tier `_meta`。
8. 命令：`/plan`、`/usage`、`/logout` 的原生命令结果与 Paseo 命令列表、账号状态联动。
9. MCP：stdio/http/sse 各一次真实调用；再用 `eagerMcpServers`、`mcpMaxOutputBytes`、`enabledTools`/`disabledTools` 检查执行效果。
10. 错误：真实 502 长等待下的计划重试、HTTP 状态通知、终态 JSON-RPC 失败、诊断正文零泄漏；同一 prompt 对照官方原版。
11. 长任务与并发：先单会话长任务，再跑矩阵；矩阵先修记录器终态判定，再恢复 80 轮。
12. 已验收项只做回归，不重测全能力；每个差异记录官方原版、适配器 wire、Paseo 时间线三层证据。
